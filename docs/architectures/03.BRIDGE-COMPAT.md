# 03. Bridge, Authentication & Upstream Compatibility

## Orbit Bridge Endpoints

All bridge routes live under `/api/v1/orbit` on the same origin:

### CS -> Backlog (`/api/v1/orbit/accounts/{account_id}/...`)

Requires Pulsar `CurrentUser` + `require_account` authorization:

| Method & Path | Purpose |
| --- | --- |
| `GET /config` | Read default Orbit destination (workspace, project, mode, state, priority, auto-note toggle) |
| `PUT /config` | Save default destination in Pulsar `integrations_hooks` (`app_id = 'orbit'`) |
| `GET /meta` | List Saturn workspaces, projects, workflow states, and labels available to assign |
| `POST /issues` | Create Saturn `issues` row (`work_item` or `intake_issue`), create `issue_links` back to `/app/accounts/{id}/conversations/{cid}`, optionally copy Pulsar chat attachments into Saturn `file_assets` + disk storage (`include_attachments: true`) |
| `GET /conversations/{cid}/issues` | List linked Saturn work items with live state name/group/color and clickable Saturn URL |
| `DELETE /conversations/{cid}/issues/{link_id}` | Unlink a Saturn item from the CS conversation |

### Unified 1x SSO (`/api/v1/orbit/auth/...`)

| Method & Path | Flow |
| --- | --- |
| `POST /sync_saturn` | Validates Pulsar session -> auto-provisions/matches Saturn user by lowercase email -> sets Saturn `session-id` cookie |
| `POST /exchange_saturn` | Validates Saturn `session-id` cookie -> auto-provisions/matches Pulsar agent -> returns `access-token`, `client`, `uid` headers |
| `POST /sign_out` | Invalidates active Saturn session & deletes matching `session-id` cookie on unified sign-out |

## Argon2id Password Hashing & Legacy Compatibility

Orbit upgrades login password hashing across **both** engines to **Argon2id** (`argon2 0.5`, OWASP 2024 parameters: `$argon2id$v=19$m=19456,t=2,p=1$...`, 16-byte CSPRNG salt):

- **Pulsar (`crates/pulsar/src/auth.rs`):** `hash_password_sync` / `hash_password` produce Argon2id PHC hashes stored in `users.encrypted_password` across sign-up, seed, password reset, MFA checks, platform user API, inbox agent/bot creation, and super-admin creation. `verify_password` verifies `$argon2*` and falls back to `$2*` `bcrypt`, transparently upgrading legacy Chatwoot/Pulsar passwords on successful login.
- **Saturn (`crates/saturn/src/session.rs` & `auth.rs`):** `hash_password` produces Argon2id PHC strings (~97 chars, fitting comfortably within `users.password varchar(128)`). `check_password` verifies `$argon2*` and falls back to Django `pbkdf2_sha256$...`; both user `sign_in` and `admin_sign_in` offload hashing to `tokio::task::spawn_blocking` and transparently upgrade legacy Plane/Django hashes before session creation.
