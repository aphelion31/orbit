# 03. Bridge, Authentication & Upstream Compatibility

## Orbit Bridge Endpoints

All bridge routes live under `/api/v1/orbit` on the same origin:

### CS -> Backlog (`/api/v1/orbit/accounts/{account_id}/...`)

Requires Pulsar `CurrentUser` + `require_account` authorization:

| Method & Path | Purpose |
| --- | --- |
| `GET /config` | Read default Orbit destination (workspace, project, mode, state, priority, auto-note toggle) |
| `PUT /config` | Save default destination in Pulsar `integrations_hooks` (`app_id = 'orbit'`) |
| `GET /meta` | List Saturn workspaces, projects, workflow states, and labels available to assign |
| `POST /issues` | Create Saturn `issues` row (`work_item` or `intake_issue`), create `issue_links` back to `/app/accounts/{id}/conversations/{cid}`, optionally copy Pulsar chat attachments into Saturn `file_assets` + disk storage (`include_attachments: true`) |
| `GET /linked_issues?conversation_id={cid}` | List linked Saturn work items with live state name/group/color and clickable Saturn URL |
| `POST /unlink_issue` | Unlink a Saturn item (`conversation_id`, `link_id`) from the CS conversation |

### Custom Theme Engine (`/api/v1/orbit/theme*`)

| Method & Path | Purpose |
| --- | --- |
| `GET /api/v1/orbit/theme` | Read persisted theme (`mode`, `preset`, `primary`, `radius`, `surface`), defaulting to Orbit Jade (`#2E9B78`) |
| `PUT /api/v1/orbit/theme` | Update workspace theme (accepts Pulsar headers or Saturn `session-id` cookie) across 8 presets + custom `#RRGGBB` |
| `GET /api/v1/orbit/theme.js` | Serve dynamic theme & Pulsar CS Desk switcher dock into Saturn SPAs |

### Unified 1x SSO (`/api/v1/orbit/auth/...`)

| Method & Path | Flow |
| --- | --- |
| `POST /sync_saturn` | Validates Pulsar session -> auto-provisions/matches Saturn user by lowercase email -> sets Saturn `session-id` cookie |
| `POST /exchange_saturn` | Validates Saturn `session-id` cookie -> auto-provisions/matches Pulsar agent -> returns `access-token`, `client`, `uid` headers |
| `POST /sign_out` | Invalidates active Saturn session & deletes matching `session-id` cookie on unified sign-out |

## Argon2id Password Hashing & Upstream Compatibility

Orbit tracks **Pulsar (`Chatwoot 4.20.1` parity, schema `20261125100456`)** and **Saturn (`v0.3.1`+)**:

- **Chatwoot 4.20.1 schema & parity (`crates/pulsar/migrations/0008_chatwoot_4_20.sql`):** adds `conversations.last_message_at` sorting (`last_message_sort` feature flag) + 7 performance indexes, conversation list/filter rate limits, Instagram unified login, SMS callback auth enforcement (`secret` + `callback_auth_enforced`), Shopify integration updates, Captain MCP tool `review_state`, Help Center enhancements, Data Imports `rejected_rows`, and hidden-tab polling pause in Live reports.
- **Argon2id (`argon2 0.5`, OWASP 2024 parameters: `m=19456 KiB, t=2, p=1`, 16-byte CSPRNG salt):**

- **Pulsar (`crates/pulsar/src/auth.rs`):** `hash_password` / `hash_password_async` produce `$argon2id$v=19$m=19456,t=2,p=1$...` PHC hashes stored in `users.encrypted_password` and devise token hashes. `verify_password` / `verify_password_async` verify `$argon2*` and fall back to legacy `$2*` `bcrypt`, transparently upgrading legacy passwords on login.
- **Saturn (`crates/saturn/src/session.rs` & `auth.rs`):** `hash_password` / `hash_password_async` produce Django `Argon2PasswordHasher`-compatible `argon2$argon2id$v=19$m=19456,t=2,p=1$...` strings (~103 chars, fitting inside `users.password varchar(128)`). `check_password` / `check_password_async` accept both `argon2$argon2id$...` and raw `$argon2id$...` as well as legacy `pbkdf2_sha256$...`; missing/inactive/bot logins execute constant-time `verify_dummy_async()`, and legacy hashes CAS-upgrade (`AND password = $3`) on login prior to session creation.
