# 04. Deployment

## Docker Compose (recommended)

```bash
cp .env.example .env
# Edit .env and set a strong SECRET_KEY (>= 64 hex chars)
docker compose up --build -d
```

`docker/init-dbs.sql` initializes `orbit_pulsar` (with `vector` extension) and `orbit_saturn`.
Orbit listens on `:3000` (`/app/` for Pulsar CS Desk, `/` for Saturn Backlog, `/health` and `/ready` for container probes).

## Bare-metal / release binary

```bash
# 1. Build frontend & release binary
scripts/build-web.sh
cargo build --release   # target/release/orbit (~32.1 MiB on macOS arm64)

# 2. Initialize & seed both DBs
createdb orbit_pulsar
createdb orbit_saturn
PULSAR_DATABASE_URL=postgres://.../orbit_pulsar \
SATURN_DATABASE_URL=postgres://.../orbit_saturn \
  ./target/release/orbit seed admin@company.com 'Strong-Password-2026' MyCompany

# 3. Start unified server
PULSAR_DATABASE_URL=postgres://.../orbit_pulsar \
SATURN_DATABASE_URL=postgres://.../orbit_saturn \
FRONTEND_URL=https://orbit.company.com \
WEB_URL=https://orbit.company.com \
SECRET_KEY="$(openssl rand -hex 50)" \
BIND=0.0.0.0:3000 \
  ./target/release/orbit
```

## Reverse proxy & security notes

- Terminate TLS with Caddy, Nginx, or Traefik and forward HTTP + WebSocket (`/cable`, `/live/*`) to `:3000`.
- When `FRONTEND_URL` / `WEB_URL` starts with `https://`, Saturn session cookies are marked `Secure`.
- Back up **both** Postgres databases (`orbit_pulsar`, `orbit_saturn`) **and** both storage directories (`PULSAR_STORAGE_DIR`, `SATURN_STORAGE_DIR`) together so carried-over chat attachments and Saturn work-item files remain consistent.
