# 01. Overview

## What Orbit unifies

Orbit embeds **Pulsar** (customer support platform — Rust rewrite of Chatwoot) and **Saturn** (project & backlog tracker — Rust rewrite of Plane) inside one Axum process on a single port (`:3000`):

| Capability | Original upstream stack | Separate Pulsar + Saturn | Unified Orbit |
| --- | --- | --- | --- |
| CS Helpdesk (`Chatwoot`) | Rails (Puma) + Sidekiq + Redis + Vite/Vue | Pulsar binary (`:3000`) | Mounted at `/app/`, `/api/v1/*`, `/cable`, `/widget`, `/sdk.js` |
| Project & Backlog (`Plane`) | Django + Celery + Beat + RabbitMQ + Redis + Node live + Caddy + MinIO (~9 containers) | Saturn binary (`:8000`) | Mounted at `/`, `/god-mode/`, `/spaces/`, `/api/*`, `/live/*` |
| CS -> Engineering bug escalation | External webhooks + manual copy/paste + separate logins | 2 ports, CORS, brittle webhook retries | **In-process Rust bridge** (`/api/v1/orbit/*`), 1x SSO, auto-carried attachments, live status notes |

## Request & event architecture

1. **Pulsar sub-router** serves all Chatwoot-compatible CS routes (`/auth/*`, `/api/v1/*`, `/api/v2/*`, `/platform/*`, `/public/*`, `/super_admin/*`, `/cable`, `/hc`, `/widget`, `/sdk.js`) and the Pulsar React Router SPA at `/app/`.
2. **Saturn sub-router** serves Plane-compatible project/backlog APIs (`/auth/sign-in/`, `/api/workspaces/*`, `/god-mode/`, `/spaces/`, `/live/*`) and the three prebuilt Saturn SPAs (`web` at `/`, `admin` at `/god-mode`, `space` at `/spaces`).
3. **Orbit bridge (`crates/orbit/`)** holds both `Pulsar` and `Saturn` library states (`OrbitState`) and wires:
   - **Direct CS -> Backlog creation** from right-clicking any Pulsar chat bubble (`Masukin Backlog (Orbit)`).
   - **Account-configurable default destination** stored in Pulsar's `integrations_hooks` (`app_id = 'orbit'`).
   - **Live Saturn -> Pulsar status sync** via an in-memory `tokio::sync::broadcast` bus (`saturn::webhook_out::subscribe_internal()`): whenever a linked Saturn work item changes state, Orbit immediately inserts a private internal note in the linked Pulsar conversation and pushes it over ActionCable (`/cable`).
   - **Bidirectional 1x Unified SSO** exchanging Pulsar devise headers <-> Saturn `session-id` cookies on the same origin.

## Limits

- Separate PostgreSQL databases (`PULSAR_DATABASE_URL` with `pgvector` and `SATURN_DATABASE_URL`) keep Chatwoot and Plane schemas 100% isolated and migration-compatible.
- In-process status sync runs inside the single Orbit process (`tokio::sync::broadcast`); multi-replica deployments require external queue fan-out if scaled horizontally.
